# 机械臂关节运动说明

## 结论

当前 Python ICP 闭环代码使用的是：

1. ICP 计算出末端在笛卡尔空间需要补偿的位姿误差。
2. 用本地 Jacobian 把这个小的笛卡尔误差近似换算成关节角增量。
3. 通过 Dobot 的 `MovJ` 服务发送关节目标。

这不是因为机械臂不能做点位运动，而是因为当前代码里 `MovJ` 是已验证更稳定的执行通道；`MovL`/`ServoP` 属于笛卡尔点位或伺服方式，理论上更直接，但在本项目记录里曾出现过不可靠或异常，因此 Python 主线暂时绕开了它们。

## 为什么用了 Jacobian

ICP 给出的结果天然是笛卡尔空间里的 6 维误差：

```text
dx, dy, dz, dRx, dRy, dRz
```

但当前 Python 控制通道最终调用的是 `MovJ`。`MovJ` 需要的是 6 个关节角目标：

```text
J1, J2, J3, J4, J5, J6
```

所以中间必须做一次转换：

```text
末端笛卡尔误差 -> 关节角增量
```

当前代码用的是数值 Jacobian：

```python
dtheta = pinv(J) @ cart
target_j = current_j + dtheta
robot.movj(target_j)
```

含义是：在当前关节姿态附近，估计每个关节微小变化会让末端产生多少位移和旋转，然后反算出一组关节增量。

## 机械臂不是可以点运动吗

可以。Dobot 服务里至少有几类方式：

### MovJ

关节运动。

服务定义：

```text
bool mode
float64 a b c d e f
string[] param_value
```

当前代码使用：

```python
req.mode = True
req.a ... req.f = joint_angles
```

也就是把目标解释为关节角。优点是稳定、简单、当前项目里验证最多。缺点是如果目标来自笛卡尔误差，就需要自己做 IK/Jacobian。

### MovL

直线笛卡尔运动。理论上可以直接给末端位姿点。

但当前 `servoing.py` 顶部注释里写了：

```text
JointMovJ: 完整6DOF (CR5 MovL已移除)
```

说明之前尝试后把 MovL 从主流程移除了。原因可能是服务返回、轨迹、坐标系、工具/用户坐标系或控制器状态不稳定。

### ServoP

笛卡尔伺服点位。C++ 连续伺服实验里使用过 `ServoP`，适合高频小步目标。

但 C++ 文件里也有注释：

```text
ServoP 在本机已验证会触发 ERROR，不用于偏移键。
```

所以它适合继续实验，但不能直接替换当前 Python 主线。

### InverseKin

控制器也提供逆解服务。理论上可以把目标笛卡尔位姿发给 `InverseKin`，由控制器返回关节角，再用 `MovJ`。

这会比本地 Jacobian 更像“机械臂自己算 IK”。但需要解决：

- 坐标系参数 `user/tool` 是否正确。
- 姿态格式是否与 `ToolVectorActual` 一致。
- 多解时选择哪一个解。
- 是否能稳定避开奇异和关节限位。

## 当前 Jacobian 的优点

1. 只用于小误差补偿，计算简单。
2. 不依赖控制器 IK 服务。
3. 输出仍然走 `MovJ`，执行通道稳定。
4. 适合 ICP 闭环这种“每次只补一点”的场景。

## 当前 Jacobian 的缺点

1. 它是局部线性近似，大步移动会不准。
2. 如果机械臂接近奇异位形，`pinv(J)` 会放大误差。
3. 如果 URDF 尺寸、关节轴、姿态约定和真实机械臂不完全一致，反算会带系统误差。
4. 一次 Jacobian 打到终点不一定准确，需要到达后再读实际位姿二次补偿。

因此相对拖拽点代码已经改成：

```text
第一次 Jacobian 到目标附近
读取实际 ToolVectorActual
第二次 Jacobian 补剩余误差
```

## 什么时候应该不用 Jacobian

如果后续验证 `MovL` 或 `ServoP` 在当前控制器上稳定，优先级应该是：

1. 小步连续闭环：优先 `ServoP`
2. 单次笛卡尔点位：优先 `MovL`
3. 笛卡尔目标转关节：优先控制器 `InverseKin + MovJ`
4. 兜底方案：本地 Jacobian + MovJ

也就是说，Jacobian 不是最终最优方案，而是当前项目里“能跑、可控、稳定”的保守方案。

## 建议下一步

建议单独做一个运动接口验证脚本，不混 ICP：

1. 读取当前 `ToolVectorActual`。
2. 构造一个小目标，例如 `+2mm X`。
3. 分别测试：
   - `MovL`
   - `ServoP`
   - `InverseKin + MovJ`
   - 本地 Jacobian + MovJ
4. 每次运动后读取 `ToolVectorActual`，打印实际误差。

只有确认某个笛卡尔点动服务稳定，才建议把 ICP 主流程从 Jacobian 切过去。

## 当前代码保持 Jacobian 的原因

一句话：

```text
ICP 输出的是笛卡尔误差，但当前可靠执行接口是 JointMovJ，所以用 Jacobian 把小笛卡尔误差换成关节增量。
```

这不是机械臂不能点运动，而是目前还没有把控制器的笛卡尔点动接口验证到足够稳定。
