# 连续 ICP 视觉伺服可行性与实验方案

本文讨论一个目标：机械臂不再按“停稳 -> 采点云 -> ICP -> 下发一步运动”的方式工作，而是在运动过程中持续采点云、持续计算误差，并持续向参考帧 `ref` 逼近。

结论先写清楚：有可能做成“近似连续伺服”，但不建议直接用普通 `MovJ/MovL/RelJointMovJ` 队列命令堆点。更可行的主路线是 `ServoJ` 小周期目标流；`MoveJog` 只能作为低级点动验证或退路，因为它是立即指令，但不能给目标点，只能指定单轴或单方向持续运动。

## 1. 指令能力判断

从 DOBOT V4 指令集看，命令分两类：

| 指令类型 | 特点 | 对连续伺服的影响 |
| --- | --- | --- |
| 队列指令 | 下发后进入算法队列，由控制器规划执行；返回成功只表示接收成功 | 容易产生队列滞后，视觉误差已经变了，旧目标还在执行 |
| 立即指令 | 下发后立即生效 | 更适合实时控制，但可表达的运动形式有限 |

相关指令：

| 指令 | 类型 | 能否给目标点 | 适合程度 |
| --- | --- | --- | --- |
| `MovJ` | 队列 | 可以 | 不适合连续伺服，适合离散补偿 |
| `MovL` | 队列 | 可以 | 理论可用，当前 CR5 固件兼容性不稳定 |
| `RelJointMovJ` | 队列 | 可以给关节增量 | 会排队，不适合高频闭环 |
| `ServoJ` | 队列 | 可以给 6 关节目标和 `t` | 最值得实验，设计目的就是动态跟随 |
| `ServoP` | 队列 | 可以给笛卡尔目标和 `t` | 可实验，但本项目已有 `MovL` 兼容性风险 |
| `MoveJog` | 立即 | 不可以，只能给 `J1+`/`X-` 这类方向 | 可低速点动，不能直接“去某点” |
| `Stop`/`MoveJog()` | 立即 | 停止 | 必须保留为安全停止 |

`MoveJog` 的本质类似按住示教器上的某个轴：`J1+`、`J1-`、`X+`、`Z-` 等。它可以立即改变运动状态，但一次只能表达一个方向，不能发送 6 维目标点，也不能指定“运动到 ref 帧”。

## 2. 为什么普通队列运动不适合连续伺服

当前离散闭环是：

```text
停稳
  -> 采当前点云
  -> ICP(current -> ref)
  -> 算一次补偿
  -> JointMovJ
  -> 再停稳
```

如果直接改成“不断计算，不断下发 `MovJ`”，会出现三个问题：

- 队列滞后：第 `k` 帧算出的目标点进入队列时，机械臂可能还在执行第 `k-2` 个目标。
- 过期目标：ICP 基于旧位姿计算，目标点越排越多，反而可能振荡。
- 无法覆盖：普通队列点已经规划，新的视觉误差不能立刻替换旧目标，只能继续排队或 `Stop`。

因此连续伺服必须满足一个原则：控制器只执行“最新目标附近的小步”，不能积压历史目标。

## 3. 推荐主方案：ServoJ 小周期目标流

思路：把连续伺服拆成两个线程，视觉线程持续更新最新误差，运动线程以固定周期发送很小的关节目标。每次只根据最新 ICP 结果向 `ref` 逼近一小步。

```text
视觉线程 10-20 Hz:
  采点云
  -> 下采样
  -> ICP(current -> ref)
  -> 输出最新 T_icp 和质量分数

运动线程 20-50 Hz:
  读取当前关节角和最新 T_icp
  -> T_icp 转工具坐标补偿
  -> 限幅
  -> 雅可比伪逆得到小关节增量
  -> ServoJ(q_now + dq, t=控制周期)
```

关键不是“把很多点排进队列”，而是“每次只送下一个很近的目标”。`ServoJ` 的 `t` 参数范围是 `[0.004, 3600.0] s`，可先从 `t=0.05-0.10 s` 做低频验证。

建议初始参数：

| 项目 | 初值 |
| --- | --- |
| 视觉计算频率 | `5-10 Hz` 起步 |
| 运动发送频率 | `10-20 Hz` 起步 |
| `ServoJ t` | `0.05-0.10 s` |
| 单周期平移限幅 | `1-3 mm` |
| 单周期旋转限幅 | `0.2-0.5 deg` |
| 单周期关节限幅 | `0.2-0.5 deg` |
| 速度倍率 | `5-10%` |
| 质量门控 | ICP 不合格则保持或减速，不发新目标 |

控制律：

```text
T_icp: current -> ref
T_delta = X * T_icp * X^-1
T_correction = inverse(T_delta)

取小比例：
  dx = clamp(log(T_correction), 每周期限幅)

关节增量：
  dq = J(q_now)^+ * dx

目标：
  q_cmd = q_now + dq
  ServoJ(q_cmd, t=dt, aheadtime=50, gain=500)
```

安全策略：
- 不允许队列堆积：运动线程只按固定周期发一个新目标；如果服务调用延迟超过周期，降低频率。
- ICP 质量不合格连续 `N=3` 次，停止发送 `ServoJ`，调用 `Stop()` 或保持当前位置。
- `|T_icp|` 超出范围时不连续伺服，回退到原来的离散 `JointMovJ` 闭环。
- 任意时刻保留键盘急停：`Stop()`、`EmergencyStop()`。

## 4. MoveJog 方案：可做低级实验，不适合作主控制

`MoveJog` 可以立即开始某个轴的运动，停止需要再下发 `MoveJog()` 或 `StopMoveJog`。它的优势是立即生效，劣势是无法给目标点。

可做的实验是“符号控制”：

```text
ICP 得到误差 e
  -> 选误差最大的一个自由度
  -> 映射到 J1+/J1-/... 或 X+/X-/...
  -> MoveJog(axis)
  -> 运行 50-150 ms
  -> MoveJog() 停止
  -> 重新计算
```

这相当于“孩子一个关节一个关节地点动”：能证明误差方向是否正确，能低速靠近 ref，但效率低、抖动大、6 维耦合差，不适合作最终视觉伺服。

适用场景：
- 验证补偿方向是否正确
- 在 `ServoJ` 不稳定时做安全退路
- 做低速、单轴、低风险的接近实验

不适用场景：
- 需要平滑 6D 轨迹
- 需要同时补偿平移和旋转
- 需要精确到达 `ref` 帧

## 5. 备选方案：StartRTOffset + OffsetPara

指令集中有 `StartRTOffset`、`EndRTOffset`、`OffsetPara`：

```text
StartRTOffset()
  -> 运动过程中周期发送 OffsetPara(x,y,z,rx,ry,rz)
  -> EndRTOffset()
```

它的思路更接近“运行中叠加实时偏移”，理论上很适合视觉伺服。但是当前 ROS2 驱动里只看到 `StartRTOffset.srv` 和 `EndRTOffset.srv`，没有看到 `OffsetPara.srv` 暴露出来。因此这条路线需要先补驱动接口，不能直接作为当前实验主线。

验证顺序：
- 先用 TCP 29999 端口手动发送 `OffsetPara`，确认控制器支持
- 再补 ROS2 service：`OffsetPara.srv`
- 最后测试运动过程中周期叠加小偏移是否生效

## 6. 实验路线

### 实验 A：ServoJ 单独动态跟随

目的：确认 CR5 是否能稳定接受 `ServoJ` 小周期目标流。

步骤：
- 固定相机不参与，只读取当前关节角
- 生成一个很小的正弦关节轨迹，例如 J1 振幅 `1 deg`，频率 `0.1 Hz`
- 以 `10 Hz` 发送 `ServoJ(q_cmd, t=0.1)`
- 记录 `GetAngle` 和 `ToolVectorActual`

通过标准：
- 机械臂运动连续，无明显一停一顿
- 服务返回 `res=0`
- 不触发 ERROR
- 停止发送后能安全停下

### 实验 B：ServoJ + 人工误差闭环

目的：验证控制律，不引入 ICP 噪声。

步骤：
- 人工设定一个小的工具坐标误差，例如 `dx=[5 mm, 0, 0, 0, 0, 0]`
- 用当前雅可比计算 `dq`
- 以 `ServoJ` 连续发送小步目标
- 观察 `ToolVectorActual` 是否按预期方向移动

通过标准：
- `+X/-X/+Z/-Z` 方向都正确
- 单周期限幅有效
- 误差减小时速度自动降低

### 实验 C：ServoJ + ICP 连续伺服

目的：验证真正的连续视觉伺服。

步骤：
- 按原流程 `r` 录制 ref 模板
- 轻微扰动机械臂，扰动先控制在 `5-10 mm`、`1-2 deg`
- 视觉线程持续计算 ICP
- 运动线程持续发送 `ServoJ` 小步目标
- 收敛后停止发送目标

通过标准：
- `|t|` 单调下降或总体下降
- 最终达到 `|t| < 10 mm` 且 `|r| < 1 deg`
- 不出现队列堆积导致的过冲
- ICP 不合格时机械臂不会继续朝旧方向运动

### 实验 D：MoveJog 点动验证

目的：验证立即指令能否做低级视觉反馈。

步骤：
- 只开一个自由度，例如相机 X 方向误差
- ICP 判断误差符号
- 发送 `MoveJog(X+, coordtype=1)` 或 `MoveJog(X-, coordtype=1)`
- `50-100 ms` 后发送 `MoveJog()` 停止
- 重新计算误差

通过标准：
- 正负方向符合预期
- 停止命令可靠
- 低速下不会越过目标太多

## 7. 推荐实现结构

新增实验脚本建议命名：

```text
scripts/continuous_servoj_test.py          # 实验 A/B
scripts/continuous_icp_servo.py            # 实验 C
scripts/movejog_axis_servo_test.py         # 实验 D
```

运行结构：

```text
RobotNode:
  GetAngle / ToolVectorActual / ServoJ / Stop / recover

PointCloudNode:
  只订阅最新点云，不阻塞服务调用

PerceptionLoop:
  latest_pc -> ICP -> latest_error

ServoLoop:
  latest_error + q_now -> dq -> ServoJ

SafetyLoop:
  键盘急停 / ICP质量门控 / 关节限位 / 服务延迟监控
```

注意：不要让点云回调和机器人服务调用在同一个阻塞循环里互相抢时间。当前项目已经把 RobotNode 和 PointCloudNode 拆开，这个结构可以继续沿用。

## 8. 风险与判定

可以继续推进的信号：
- `ServoJ` 低频目标流运动平滑
- 服务延迟稳定，小于发送周期的 `50%`
- ICP 计算能稳定在 `100-200 ms` 内完成
- 小扰动下误差能连续下降

需要停止或降级的信号：
- 机器人出现明显抽动或停顿
- `ServoJ` 返回成功但机械臂不动
- 误差下降慢但关节运动变大，说明雅可比或坐标变换有问题
- ICP 结果跳变，导致目标方向频繁反转

最终判断：
- 若 `ServoJ` 能稳定工作，连续 ICP 伺服可实现。
- 若 `ServoJ` 在 CR5 上表现仍像普通队列点，连续伺服会受队列延迟限制，只能做“快速离散闭环”。
- `MoveJog` 不能作为主方案，因为它没有目标点输入，只能做单轴立即点动。
- `StartRTOffset + OffsetPara` 可能是更像实时伺服的方案，但当前驱动缺少 `OffsetPara` 接口，需要先补接口再验证。
